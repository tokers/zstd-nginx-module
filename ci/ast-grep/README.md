# Vendored ast-grep rules

GENERATED by `tools/vendor-astgrep-rules.py` -- do not hand-edit. Re-run the
generator instead, so every module stays derived from one source of truth.

## What is here

`rules/own/` -- this superrepo's C and nginx structural rules.
`rules/vendor/` -- the C/C++ slice of CodeRabbit's `essentials` ast-grep rule
pack (Apache-2.0), CWE-tagged. These are the rules CodeRabbit itself runs on a
pull request, so a local hit is a finding the bot would have raised.

Only C/C++-language rules are vendored. The upstream pack spans 15 languages;
the rest can never match a `.c` file.

## Why vendored rather than referenced

The full pack lives at `/opt/myguard/.ast-grep`, outside this repo. ast-grep
finds `sgconfig.yml` by walking up from the working directory, so a hook here
would resolve the superrepo's config only while this clone sits inside
`/opt/myguard`. Cloned standalone, ast-grep would find no config, scan against
an empty ruleset, and exit 0 -- a gate that passes everything.

## Gating

The pre-commit hook promotes a named subset to `error`; ast-grep exits non-zero
only on `error` and has no severity-threshold flag. Everything else stays
advisory -- printed, never blocking. The advisory tier is dominated by
`nginx-unchecked-palloc`, which in nginx C is frequently legitimate.

Run the full advisory sweep by hand:

    ast-grep scan -c ci/ast-grep/sgconfig.yml src/
